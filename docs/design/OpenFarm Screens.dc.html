1Open alerts is the only tinted metric

All four stat cards already exist in dashboard/page.tsx, each rendering its metric in the default foreground. Here only open alerts takes danger — one tinted number in a row of neutral ones is what makes it read first.

2Alerts moved onto the dashboard

The alert list was fetched here already and thrown away. It is the one thing a farm manager opens the app to see, so it takes the right column.

3Farm rows carry their numbers

Field count and hectares in mono beside the region. A list row that shows only a name wastes the row.

4Quick actions demoted

9Summary cards read from severity tokens

Source uses raw text-red-500 / amber-500 / yellow-500 plus an accent prop. Here icon and count both come from --sev-*, so the summary can't drift from the rows below it.

10The filter states what it hid

A filtered list with no count is a trap — the user reads four alerts and thinks that's all of them. "4 of 12 shown" is the cheapest possible fix.

11Closed rows stay put

60% opacity on a surface-2 fill, action swapped to Reopen. Closing an alert must not make the list jump under the cursor.

12Ellipsis is for user data only

Emails and names truncate because they're unbounded user input. Role badges, labels and headings never do — that's the i18n rule made concrete.

13Destructive zone is bordered, not filled

A danger border and a danger heading, on the normal card surface. A red-washed panel would fight every other card on the page for attention it doesn't deserve until clicked.

14Deletion states its blast radius

Counts the farms, fields, months of history and notes it will destroy. "This action cannot be undone" alone tells the user nothing about what they're losing.

15Pending invites live in the same list

Same row shape at 60% opacity with a mail icon instead of an avatar. A separate "pending" section splits one mental model into two.

A recipient with no account needs to know what they're holding. One outline badge in the header does it — no disabled buttons, no greyed-out chrome.

Reproducible by construction

Every pixel traces back to a scene

Four public steps, no black box in the middle. Every value in the UI carries the satellite, the date, the cloud cover and the colormap that produced it.

01

STAC search

Element84 catalogue, filtered by geometry, date and cloud cover.

02

COG generation

Index computed per scene, written to object storage as a cloud-optimised GeoTIFF.

03

TiTiler tiles

Served with a fixed colormap, so two fields are always comparable.

04

Stats & provenance

Zonal statistics stored alongside the scene that produced them.

Re-run any analysis and get the same answer — or file an issue with the scene ID and someone else can reproduce it.

20The hero is a map, not a background

Imagery, field boundary, NDVI raster and the explained alert in one frame. For a geospatial product the fold should look like the product; a scrim gradient keeps the headline at full contrast over it.

21Four indices, one scene

The rasters are drawn from the real rdylgn and rdbu stops with each index's true rescale range. Same stressed patch visible in all four — which is how you know it isn't a cloud.

22A season as six tiles

Green-up to senescence, read left to right. This makes "24 months backfilled" a thing you can see rather than a bullet you have to believe.

23The architecture is drawn as planes

Boundaries, satellite, weather grid and soil as four skewed layers stacking into layer A — the standard GIS idiom, and it explains the A/B/C model faster than three paragraphs did.

24The pipeline shows its own output

Scene footprint → COG → tile grid → time series. Each step carries the artefact it produces, so the reproducibility claim is legible without reading the captions.

25Soil gets a cross-section

Depth bands widening downward, texture fractions darkening with depth. Subsurface data is half of what makes this an intelligence platform rather than an imagery viewer.

Raster visuals are generated stand-ins for Sentinel-2 tiles; every colour comes from the real INDEX_CONFIG ramp stops and rescale ranges.

26Home leads with the worst thing

Not four stat cards — one alert, in full, with its cause. On a phone the fold is small enough that the first element has to be the one that changes your day.

27The sheet keeps the map alive

Half detent shows the reading, the trend and the recommendation while the field stays visible above it. A full-screen panel would break the link between the number and the ground.

28One series, no band

The mobile chart drops the p10–p90 band and the threshold line. At 358px wide a distribution band is noise, and the sentence underneath already says what the trend means.

29Scouting is the reason mobile exists

Position, tag chips, note, photo, and the weather at that instant — captured in one screen, saved offline. It is the only place in the product where the phone beats the desk.

30Offline is stated, not silent

An info callout says the note will upload later. Anything else and the user taps save, sees nothing, and re-enters it back at the office.

31Everything sized for a thumb

Tab targets 52px, inputs and primary actions 48px, chips 38px, body never below 14px. The primary action sits at the bottom on every screen.
