The OpenFarm design system

A single visual language for an open, modular field intelligence platform — so that satellite, weather, soil and time all speak in the same colour, the same type, and the same units, no matter which contributor built the screen.

Built on the existing shadcn/ui + Tailwind foundation. Every token name in the current globals.css is preserved, so adoption is additive — nothing has to be rewritten to start using it.

01 — Principles

Five rules that decide every argument

When two options both look fine, the one further up this list wins.

01

The number is the interface

Chrome recedes; measured values are the loudest thing on screen. Mono, tabular, high contrast, never truncated. Decoration that competes with a reading gets cut.

02

Every value carries its why

A score without its limiting factor, a date without its satellite, an alert without its window — all incomplete. Explainability is the product, so it is a layout requirement, not a tooltip.

03

One quantity, one colour, forever

Water is blue in the map, in the chart, in the legend and in the badge. A hue is a binding, not a decoration — reusing it for something else is the single most damaging thing you can do to this UI.

04

Dense, not cramped

Agronomists compare; comparison needs things adjacent. We buy density by removing padding and boxes — never by shrinking text below 11px or shrinking hit targets below 40px.

05

Legible to a stranger's fork

OpenFarm is self-hosted by people we will never meet. The system must survive being extended by a contributor who read only this page: predictable token names, no clever abstractions, no component that exists in one place only.

04 — Light theme

Same tokens, three things that must change

Dark is the default, but the app ships a light theme and field staff use it outdoors. Light is not "dark inverted": borders have to carry more of the structure, status hues have to darken to clear 4.5:1 on white, and elevation swaps from surface-lightness to real shadow.

Ramps never change between themes — they encode measurement, not chrome.

What changes

Status hues darken

danger 0 84% 60% → 0 72% 51%, warning 38 92% 50% → 32 95% 44%. The dark-theme values fail 4.5:1 on white.

Borders carry the structure

On dark, a card is a lighter surface. On light, the surface is the same white as the page — so the 1px border is doing all the work and can never be dropped.

Elevation becomes shadow

Shadows use hsl(150 20% 8% / 0.06–0.14), not the 0.28–0.66 of the dark theme. Reusing dark shadow values makes light mode look bruised.

Primary buttons flip their text

Dark: dark-green label on bright green. Light: white label on 142 76% 36%. Both come from --primary-foreground; never hard-code either.

What must not change
✓Index ramps. rdylgn and rdbu are scientific scales — they are identical in both themes and identical to the raster.
✓Signal hue assignments. Water stays blue, temperature stays orange. Only their lightness shifts.
✓Every size, space, radius and icon dimension.
✓Map chrome stays dark in both themes — a light panel on satellite imagery is unreadable. This is the one deliberate exception.
✕Never ship a component you have only looked at in one theme. Toggle before you open the PR — the reviewer will not.

07 — Typography

Do
Cap a screen at five text sizes. A sixth means the hierarchy is wrong, not that you need a new size. Set every changing number in tabular-nums so columns and rows stop jittering on refresh. Use mono for anything measured — index values, hectares, coordinates, ISO dates, thresholds, IDs. Sentence case everywhere. "Run NDVI analysis", not "Run NDVI Analysis".
Don't
Go below 11px. 10px exists only for uppercase micro pills, where caps buy back the x-height. Reach for an arbitrary size like text-[13.5px] — the scale has a slot for it. Set mono for prose, or sans for a value that sits in a column. Use weight 300 anywhere in product UI — it disappears on dark surfaces.

09 — Elevation & motion

Five steps, and you may not skip one

On dark surfaces a shadow reads weakly, so elevation is carried by surface lightness first and shadow second. Each step up the ladder gets both.

Never animate map pan/zoom, chart redraw, or anything the user is measuring against. Under prefers-reduced-motion, transforms are dropped and only opacity remains.

Focus

A 2px --ring outline at 2px offset, on every interactive element, in both themes. Never outline:none without a replacement.

Three things to fix in both locale files

Both files are Title Case

English has "Quick Actions", "Open Alerts", "Create Farm"; Spanish mirrors it with "Acciones Rápidas", "Alertas Abiertas". The locales agree with each other and both break the sentence-case rule in §23 — and Spanish does not title-case at all, so it is doubly wrong there. Fix both files together: "Quick actions" / "Acciones rápidas". Changing only one makes them diverge.

Hyphen used as a dash — again in both

"Get Started - It's Free" and "Comenzar - Es Gratis" both use a hyphen where the copy rules call for an em dash. Same in heroDesc in each file.

Numbers and units stay locale-aware

Format through Intl.NumberFormat — es-ES uses a comma decimal separator, so 0.703 renders 0,703. Units (ha, mm, °C) and ISO dates never translate.
